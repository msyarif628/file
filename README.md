# Sentinel — Reactive Vault Circuit Breaker with On-Chain Neural Anomaly Detection

**Track:** Reactive Meets AI (Reactive Omni Buildathon, 5 Nov – 5 Dec 2026).
**Author:** lovefratz (Muhammad Syarif) — 1.5 years bug bounty, blockchain
smart contract security. **Status:** built and tested locally; **not yet
deployed** (see `script/DEPLOY.md` for the deployment runbook).

## What it is

A vault on Ethereum Sepolia holds demo ERC-20 tokens. A reactive contract
on Reactive Lasna subscribes to that token's `Transfer` events. For every
transfer **out of the vault**, it feeds four features into a tiny quantized
neural network (4→4→1 MLP) that runs **on-chain inside `react()`** — the
model decides, in the running system, whether the outflow pattern looks
like a drain. When the anomaly score crosses the threshold, the reactive
contract requests a cross-chain callback that **pauses the vault**, freezing
further withdrawals. No bot, no server: origin event → reactive inference →
callback.

## Architecture

```
Ethereum Sepolia (chain 11155111)                Reactive Lasna (chain 5318007)
┌─────────────────────────────┐                  ┌──────────────────────────────┐
│ SentinelToken (ERC-20 demo) │  Transfer events │ SentinelReactive             │
│ SentinelVault (holds tokens,│ ───────────────► │  (AbstractReactive)          │
│  pausable; AbstractCallback)│  via subscription│  - subscribes Transfer       │
│  - pause() via callback     │                  │  - tracks vault outflows     │
│  - unpause() owner-only     │  ◄───────────────│    (60s trailing window)     │
│  - withdraw() blocked while │   callback:      │  - AnomalyModel (4→4→1 MLP)  │
│    paused                   │   pause()        │  - score >= 7000 → callback  │
└─────────────────────────────┘                  └──────────────────────────────┘
```

### Contracts (`contracts/`)

| Contract | Chain | Role |
|---|---|---|
| `SentinelToken.sol` | Sepolia | Demo ERC-20 (OpenZeppelin), owner-mintable, 18 decimals. |
| `SentinelVault.sol` | Sepolia | Holds tokens; per-depositor balances; `deposit`/`withdraw` blocked while paused; `onAnomaly` callback entry (proxy + RSC auth) + owner-only `pause`/`unpause`. |
| `SentinelReactive.sol` | Lasna | Subscribes to `Transfer`; 60 s ring buffer of last 8 vault outflows; features f1–f4 → `AnomalyModel.score`; score ≥ 7000 + 10-min cooldown → pause callback. |
| `AnomalyModel.sol` | (library) | Pure fixed-point 4→4→1 MLP, tanh hidden + sigmoid output, 0–10000. |
| `ModelWeights.sol` | (generated) | Quantized weights + standardization constants. **Generated by `ml/train.py` — never hand-edit.** |

### Features (computable from Transfer events alone)

- `f1` = log-scaled single transfer amount (log10 tokens, clamped ±6).
- `f2` = count of vault outflows in the trailing 60 s window.
- `f3` = log-scaled cumulative vault outflow in the trailing 60 s window.
- `f4` = 1 if `to` never received from the vault before, else 0.

Threshold: score ≥ **7000** (70%). Cooldown between pause callbacks:
**10 minutes**. Callback gas limit: **1,000,000** (min 100,000).

## Honest scope note

The model is a **small** quantized MLP (4 inputs, 4 hidden, 1 output),
trained off-chain on **synthetic** normal-vs-drain data. It is a proof that
on-chain neural inference can drive a reactive security action — not a
claim of a large model, and not a production drain detector. Testnet only,
demo tokens only, no real value. Measured test-set performance (synthetic):
**98.25% accuracy, 97.7% drain recall** (see `ml/train.py` output).

What the tests prove: the Solidity model reproduces the trainer's
fixed-point simulation **exactly (max abs diff 0 across 8 vectors)**;
normal withdrawals never request a callback; a drain burst does — on the
first transfer; non-vault transfers, wrong topics/opcodes, and non-system
callers are ignored; the 10-minute cooldown and `resetPauseFlag` re-arm work.

## Deploy (testnets only)

Full runbook: [`script/DEPLOY.md`](script/DEPLOY.md). Summary:

1. Get Sepolia ETH (public faucet) → swap 0.1 ETH for 10 lREACT via the
   faucet contract `0x9b9BB25f1A81078C544C829c5EB7822d747Cf434`.
2. Predict the RSC address (`cast compute-address`, deployer + next nonce).
3. `forge script script/DeploySepolia.s.sol --rpc-url $SEPOLIA_RPC
   --private-key $PRIVATE_KEY --broadcast` (token + vault).
4. Deploy the RSC on Lasna with `forge create` (or `cast send --create`) —
   **never `forge script`** (the constructor calls the system contract).
5. `setRecipient(vault)` on the RSC; fund both sides (`depositTo` for the
   RSC, ETH already in the vault).
6. Verify on Reactscan, then run `bash script/demo.sh`.

## Deviation log — the published library is NOT the documented Omni API

This is the most important section for anyone reviewing or redeploying
this repo. **DESIGN.md was written from the current docs at
dev.reactive.network, which describe an Omni API that does not exist in
the only published library.**

What I verified (2026-11-17, in this repo):

- `forge install Reactive-Network/reactive-lib` (README-confirmed command)
  installs **v0.2.0** (Dec 2024 prerelease; `main` is one commit ahead and
  identical except a remapping + one line). It is the **pre-Omni RVM-era**
  library.
- The docs' import paths (`@reactive/src/base/AbstractReactive.sol`) do
  not exist in it: the real paths are
  `src/abstract-base/AbstractReactive.sol`,
  `src/abstract-base/AbstractCallback.sol`,
  `src/interfaces/{ISystemContract,IReactive,IPayable}.sol`.
  Its own remapping is `@reactive/=src/`.
- The docs' Omni surface is **absent**: no `SYSTEM` constant, no
  `onlySystem`, no `requestCallbackV_1_0`, no `CallbackConfiguration_V_1_0`,
  no `AbstractCallback(IPayable, address)`, no `onlyServiceProvider` /
  `onlyCallbackSender`. Grep over the whole `src/` confirms zero matches.
  `LogRecord` uses snake_case fields (`topic_0`, `op_code`, `data`, ...).
- The official demos repo (`Reactive-Network/reactive-smart-contract-demos`,
  `main`) uses this same legacy library, and its Basic Demo is the pattern
  this repo follows.

What this repo does instead (same concept, same architecture, same
thresholds — only the protocol binding differs):

- **Subscribe** via the Omni system contract
  `0x8888888888888888888888888888888888888888` (the address the current
  docs publish; the 2026-10-28 migration post says "a new system contract
  now handles" subscriptions, "keeping the same signature"). Low-level call
  in the constructor, success required — a high-level interface call
  reverts in forge tests against a code-less address (verified by probe).
- **`react()` guard**: explicit `msg.sender == SYSTEM_OMNI ||
  msg.sender == address(service)` — the docs' `onlySystem` semantics.
  NOT the demos' `vmOnly`: that modifier is RVM-era and keys off whether
  the legacy system contract has code at `0xfffFfF`; on Omni's single
  deployment it cannot distinguish the caller and would brick `react()`.
- **Callbacks**: **`emit Callback(...)` does NOT deliver on this Omni
  deployment — proven live, twice (2026-11-17).** The migration post
  claims "old-style callbacks still work", but v1 (Omni-only subscribe)
  and v2 (Omni + legacy subscribe) both fired `react()`, emitted
  `Callback`, set the RSC latch — and the callback NEVER arrived on
  Sepolia after 8+ minutes (vault ETH untouched, no `VaultPaused`).
  The working path is the docs' current API: a low-level call to
  `SYSTEM_OMNI.requestCallbackV_1_0` with the
  `CallbackConfiguration_V_1_0` struct (chainId, recipient, gasLimit,
  payload) — the published lib does not declare it, so it is called via
  `abi.encodeWithSignature` (same technique as subscribe). The legacy
  event is kept as well (tests + observability); a double delivery
  would be harmless (`onAnomaly` is idempotent). The request is NOT
  `require()`d — a failed request must not roll back the window/score
  state, and the latch only sets on success (`CallbackRequestFailed`
  is emitted otherwise).
- **Vault auth**: the library's `authorizedSenderOnly` (proxy check —
  constructor passes the Sepolia proxy as the library's
  `_callback_sender`, exactly as the Basic Demo does) **plus** an explicit
  `reactive_ == callbackSender` check (the RSC check the docs prescribe).
  The library's `rvmIdOnly` is deliberately **not** used: it compares the
  injected address against `rvm_id`, which the library sets to the
  **deployer's** address — that can never equal the RSC address, so using
  it would brick every callback.
- **Debt**: constructor authorizes the Omni system contract in
  `AbstractPayer`'s sender ACL; `coverDebtOmni()` settles debt owed to it.
  The inherited `coverDebt()` still settles with the legacy vendor.

**This is NOT a pivot to Concept B.** Concept B (cross-chain stop-loss)
uses the same library and the same auth model, so pivoting would not fix
anything — the concept (vault circuit breaker + on-chain MLP) is fully
implementable on the published library, and it is built here.

**Live verification DONE (2026-11-17, v3 deployment).** Full loop proven
end to end — see `DEPLOYED.md` for the hashes. Normal 10 SENT withdrawal
scored 3 (no pause); 5×800 SENT drain burst scored 9985 → Lasna reactive
tx → Sepolia callback tx → `VaultPaused`, `paused() = true`, bursts 3–5
reverted. Reactscan RSC v3: status `active`, subscription listed. The
legacy-service fallback (subscribe via `service` too) was tried in v2
and did NOT fix callback delivery; the fix was `requestCallbackV_1_0`
in `react()` (see the Callbacks bullet above). `demo.sh`'s `paused()`
helper used to return raw hex compared against the string `"true"`, so
it reported FAIL even when the vault had paused — fixed to return
`true`/`false`.

## Other deviations from DESIGN.md (minor)

- `solc_version` bumped 0.8.26 → **0.8.29** (forge auto-downloaded it) to
  match the docs' `pragma ^0.8.29`; the lib's pragma is `>=0.8.0` and
  OpenZeppelin 5.7.0 accepts it.
- Vault `withdraw()` is per-depositor balances (the design's "owner/any
  depositor" was ambiguous); deposits and withdrawals are both blocked
  while paused, per the design.
- Vault constructor takes the token address as well as the proxy + RSC
  address (the design's signature omitted it; the vault must know which
  token it holds).
- Tests do **not** use `vm.etch` to mock the system contract (the design
  suggested it): the constructor's subscribe is a low-level call to the
  code-less system address, which succeeds as a no-op in tests, and
  `react()` is invoked directly with `msg.sender` pranked to the system
  address.
- `testMatchesTrainerVectors` asserts **exact** equality with
  `ml/vectors.json` (observed max diff 0), not just the ±150 tolerance.
